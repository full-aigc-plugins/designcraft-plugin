## Purpose

为插件建立覆盖来源、分发、运行、宿主和创作质量的可追溯发布条件，确保候选测试与正式发行证据分开，市场元数据引用真实产物，并防止未完成任务被规格状态或历史测试替代。

## ADDED Requirements

### Requirement: RG-01 分层门禁与独立夹具

验证 SHALL 分层报告静态结构、快照、拒绝边界、共享契约兼容、Harness 场景、固定原生、宿主与创作结果；离线测试使用临时 fixture，无需真实兄弟源码或已安装插件。

#### Scenario: 只有快照测试通过
- **WHEN** 当前单项快照测试或未来静态检查通过
- **THEN** 只更新对应层结果，原生、宿主与创作仍为 NOT_RUN。

### Requirement: RG-02 当前证据绑定

每层证据 SHALL 绑定插件版本和内容摘要、技能源锁、原生版本/二进制、输入、产物、环境及运行标识；变更使证据失效时必须重验受影响层。CI 未执行或失败要明确展示。

#### Scenario: 同步新技能源
- **WHEN** 插件引入新的执行脚本摘要
- **THEN** 旧执行和相关宿主/产物证据标为待复核，不以旧报告放行新包。

#### Scenario: 输入、产物或环境身份变化
- **WHEN** 证据引用的输入、交付产物、原生运行时或验证环境摘要与当前值不一致
- **THEN** 仅将绑定这些身份的证据标为 `STALE`，并保留 CI、原生、宿主、创作和发行层各自的 `NOT_RUN` 状态，不用其他层通过替代缺失证据。

### Requirement: RG-03 来源发行与市场一致性

正式发布 SHALL 先完成技能源发行锁，再验证插件产物与宿主清单；插件版本、tag、产物摘要和市场引用必须一致。已发布身份不可静默覆盖；Git/提交/发布动作须在对应授权下执行。

#### Scenario: 候选试图进入正式市场
- **WHEN** 来源 releaseTag/commit 缺失或必要验收未通过
- **THEN** 拒绝登记正式发行，保留候选身份并列出阻塞项。

#### Scenario: 市场引用不一致
- **WHEN** 市场引用版本或 tag 与插件实际发行不同
- **THEN** 发布校验失败，不报告用户能够获得正确更新。

#### Scenario: 技能源锁离线内容与在线信任分层
- **WHEN** 离线锁中的来源文件摘要与检出源码一致，但尚未解析受信仓库的 release tag
- **THEN** 仅报告离线内容 `PASS`，在线来源保持 `NOT_RUN`，不得放行正式发行。

#### Scenario: 技能源 tag、仓库或内容摘要漂移
- **WHEN** 受信仓库不匹配、release tag 解析到不同 commit，或文件清单摘要不匹配
- **THEN** 对应校验层报告 `FAIL`，正式发行拒绝。

#### Scenario: 在线来源解析遇到网络故障
- **WHEN** 无法连接来源仓库以解析 release tag
- **THEN** 在线来源保持 `NOT_VERIFIED_NETWORK_UNAVAILABLE`，保留候选身份，不把离线摘要视为在线信任证明。

#### Scenario: 发行包、清单、市场与验收报告不一致
- **WHEN** package SHA-256、插件版本/tag、宿主清单、市场引用任一不一致，或必要验收报告缺失/非 PASS/绑定旧候选
- **THEN** 发行候选门禁失败，并给出对应差异；不能因报告引用自身写有 `PASS` 就放行。

### Requirement: RG-04 完成归档与后续范围

实现任务 SHALL 只在对应代码和验收完成后勾选；主规范同步及归档须在本变更验收满足后进行。额外平台、其他宿主、自动多轮和 ArtCraft 接入必须在独立后续变更中记录，不能以占位配置计为本次完成。

#### Scenario: 计划产物全部存在
- **WHEN** proposal/design/specs/tasks 已通过 OpenSpec 格式验证
- **THEN** 只报告规划完成，实施任务仍未完成，不执行同步归档。
